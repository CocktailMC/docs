# 代码评审

至少一名熟悉该仓库的成员批准后才能合并。作者不批准自己的 PR。只有一名成员能审时，在 PR 里写明自测命令和结果，仍按下面的清单过一遍。

## 所有仓库

- 改动和标题是同一件事。
- 默认分支上的无关格式化被剔除。
- 没有密钥、令牌、玩家数据、本地 `data/` 数据库。
- 错误路径有明确行为：拒绝启动、返回错误码，或写审计日志。不吞掉失败。
- 新配置有默认值，旧配置在不迁移时的行为写在 PR 里。

## Cocktail

- 控制面 API 与 React 管理端一起改。只改一端时说明另一端何时跟上。
- 插件通过 `cocktail-plugin-sdk` 调用宿主。不在插件里直接请求 `127.0.0.1` 上的控制面端口来模拟 `cocktail_control`。
- 实例热接管：重启控制面不能把仍在跑的服务器显示成已停止。
- Windows 防火墙与踢连接保持「需要管理员」的现有行为，不在普通权限下假装成功。
- 工作区版本号只按 [versioning.md](../versioning.md) 调整。

## ESPlus

- 许可是 LGPL-3.0-or-later。不要把 Apache-2.0 文件头批量盖到本仓库。
- 面板密码、RSA 包装密钥、sudo 口令不进 argv、不进 `application-runtime.properties`、不进审计明文。
- 指令门禁默认关闭。新指令进入 `protectedCommands` 时写明风险级别。
- 客户端与服务端协议一起改。只改一边会导致密码窗或 sudo 包对不上。
- SemVer：破坏配置或权限模型时升 minor 或 major，并写迁移说明。

## leaf

- 模组边界保持 C ABI。新 API 加在版本化头文件里，不在边界上暴露 C++ 类型。
- 能力用 capability 位，不在模组侧分支加载器。
- 改 `LeafApi` 槽位时同步示例 `greeter` 与 live 安装树，避免旧包错位崩溃。
- 桥接 JAR 只引导引擎。加载 `.leafmod` 的逻辑留在引擎。

## 文档仓库

- 与源码矛盾时，以当前默认分支的源码为准，改文档。
- 不把 `项目方案.md` 里的收入预测写进流程，除非该节明确标注为草案摘要。
- 流程变更本身走 PR，便于以后对照。
