# 文档维护

## 写在哪里

| 内容 | 位置 |
|---|---|
| 组织有哪些仓库、许可、怎么协作发版 | 本仓库 |
| Cocktail 版本字符串 | [versioning.md](../versioning.md)，不要在别处再定义一套 |
| 控制面功能表、环境变量、打包命令 | `Cocktail` 仓库 `README.md` |
| 产品线商业草案 | `Cocktail` 仓库 `项目方案.md`。引用时标明草案日期 |
| ES+ 安装、指令、配置 | `ESPlus` 仓库 `README.md` 与 `OVERVIEW.md` |
| Leaf 模块设计与进度 | `leaf` 仓库 `docs/architecture/` |
| 修复叙事、一次性排障 | 留在该仓库的 `docs/` 或 Issue，不搬进本手册 |

本仓库描述行为，不复制大段源码。源码变了，更新对应的项目页和流程页里会过期的命令、版本号、默认分支。

## 修改流程

文档改动走和代码一样的 PR，见 [pull-requests.md](pull-requests.md)。只改本仓库时，验证段写「通读链接」即可。

同时改了源码和约定时：

1. 先合并源码仓库的 PR。
2. 再改本仓库，链到那个合并提交。

避免手册比默认分支超前，也避免手册停留在已经删除的命令上。

## 文风

- 用现在时写已经存在的行为，用「尚未」写还没落地的流水线。
- 命令可复制。路径使用仓库里的真实相对路径。
- 表格适合对照仓库、阶段、命令。长流程用有序列表。
- 不把未实现的安装器参数写成用户已经能执行的命令。

## 索引

新增一篇流程时：

1. 放到 `process/`，文件名用英文短横线。
2. 在 [process/README.md](README.md) 和仓库根 [README.md](../README.md) 各加一行。
3. 若它改变发版或版本号，在 [release.md](release.md) 链过去，并检查 [versioning.md](../versioning.md) 是否仍然自洽。版本规范本身的修改单独开 PR，标题以 `docs: versioning` 开头。
